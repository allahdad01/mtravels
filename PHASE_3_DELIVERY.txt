ENCRYPTION IMPLEMENTATION
================================================================================

WHEN SENDING MESSAGE (POST):
  1. User submits message via API
  2. MessageEncryption.encrypt() called
  3. Generate random IV (16 bytes)
  4. Encrypt with AES-256-CBC
  5. Base64 encode (IV + ciphertext)
  6. Store encrypted_content in database
  7. Set is_encrypted = 1, encryption_key_id = N
  8. Set content = NULL (to save storage)
  9. Return success to user

WHEN RECEIVING MESSAGE (GET):
  1. Query messages from database
  2. For each message with is_encrypted = 1:
  3. Load encryption key from secure storage
  4. Base64 decode encrypted_content
  5. Extract IV (first 16 bytes)
  6. Decrypt with IV and key
  7. Replace content with decrypted text
  8. Remove encryption metadata from response
  9. Return plaintext to user

KEY MANAGEMENT:
  1. Create unique key per tenant
  2. Generate 32 random bytes (256-bit)
  3. Store key in secure_keys/ directory (0600 perms)
  4. Store key hash in database (for verification)
  5. Cache key in memory during request
  6. Support key rotation (retire old, create new)

ENCRYPTION OVERHEAD:
  Per-message encryption: ~1-2ms
  Per-message decryption: ~1-2ms
  Key generation: ~100ms (one-time)
  Key loading/caching: ~0.1ms (subsequent)

  Plaintext 100 bytes → Encrypted ~135 bytes
