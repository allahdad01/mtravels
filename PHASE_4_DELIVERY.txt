DATABASE INFORMATION
================================================================================

MAIN TABLE: chat_audit_log

Columns:
  - id (BIGINT) - Primary key
  - tenant_id (INT) - Tenant reference
  - branch_id (INT) - Branch reference
  - user_id (INT) - User performing action
  - action (VARCHAR) - Operation type
  - target_user_id (INT) - Affected user
  - message_id (BIGINT) - Message reference
  - room_id (VARCHAR) - Chat room ID
  - details (JSON) - Additional context
  - ip_address (VARCHAR) - Client IP
  - user_agent (VARCHAR) - Browser info
  - status (VARCHAR) - success/denied/failed/error
  - error_message (TEXT) - Error details
  - created_at (TIMESTAMP) - When it happened

Indexes:
  - PRIMARY KEY on id
  - idx_tenant_action (tenant_id, action, created_at)
  - idx_user_time (user_id, created_at)
  - idx_target_user (target_user_id, created_at)
  - idx_message_id (message_id)
  - idx_status (status, created_at)
  - idx_action_time (action, created_at)

ARCHIVE TABLE: chat_audit_log_archive
  - Same structure as main table
  - Additional column: archived_at
  - For storing logs older than 90 days

PERFORMANCE METRICS
================================================================================

EXPECTED LOG VOLUME:
  - Per message: 1-3 audit entries (send, encryption, read)
  - Per day (100 users, 500 messages): ~1,500 entries
  - Per month: ~45,000 entries
  - Per year: ~540,000 entries

STORAGE ESTIMATE:
  - Per entry: ~200 bytes
  - 1 year of data: ~100 MB
  - With archive rotation: ~50 MB active + historical

QUERY PERFORMANCE:
  - Simple query (by tenant, last 100): <10ms
  - Filtered query (complex): <50ms
  - Summary query (7-day stats): <100ms

RECOMMENDATION:
  - Archive logs older than 90 days monthly
  - Use ChatAudit::archiveOldLogs() for cleanup
  - Monitor database size quarterly

================================================================================
TROUBLESHOOTING
================================================================================

ISSUE: No logs appearing in admin interface
  SOLUTION:
    1. Check migration was applied (verify_phase4.php)
    2. Check ChatAudit is included in api files
    3. Send a test message
    4. Check error logs for exceptions

ISSUE: Performance degradation
  SOLUTION:
    1. Check indexes exist: SHOW INDEX FROM chat_audit_log
    2. Archive old logs: ChatAudit::archiveOldLogs($tenantId, 90)
    3. Check table size: SELECT COUNT(*) FROM chat_audit_log
    4. Consider partitioning if > 1M rows

ISSUE: Export shows no data
  SOLUTION:
    1. Verify logs exist in database
    2. Check date range in filter
    3. Try without filters first
    4. Check PHP permissions for temp files

ISSUE: Migration fails
  SOLUTION:
    1. Check database credentials
    2. Verify user has CREATE TABLE permission
    3. Check for existing tables (may already exist)
    4. Review error message for syntax issues
