PHASE 3: MESSAGE ENCRYPTION (6-8 hours)
================================================================================

PROBLEM:
  Currently: Messages stored in plaintext
  Database admin can read all messages
  Non-compliant with HIPAA/GDPR for sensitive data

SOLUTION:
  Encrypt messages at rest in database
  Decrypt only when retrieved by authorized users
  Admin cannot read message content

IMPLEMENTATION:
  New table: encryption_keys (manage encryption keys)
  Add to chat_messages: encrypted_content, encryption_key_id, is_encrypted
  
  New class: /includes/MessageEncryption.php
  - encrypt() method
  - decrypt() method
  - key management
  
  Update /api/messages.php:
  - Encrypt on INSERT (POST)
  - Decrypt on SELECT (GET)
  
  Migration script: /includes/migrate_to_encrypted.php
  - Encrypt existing messages
  - Run in background

ENCRYPTION OPTIONS:
  Option 1: Database keys (simple, less secure)
  Option 2: AWS KMS (production-grade, cost)
  Option 3: HashiCorp Vault (enterprise, complex)

EFFORT: 6-8 hours (depending on key management)
  - Design: 1 hour
  - Encryption class: 2 hours
  - API updates: 1.5 hours
  - Migration script: 1 hour
  - Key management: 1.5 hours
  - Testing: 1 hour

PRIORITY: 🟠 MEDIUM

PHASE 5: RATE LIMITING & SECURITY (3-4 hours)
================================================================================

PROBLEM:
  Currently: No rate limiting on APIs
  Users can spam messages
  Attackers can brute-force room IDs
  No DDoS protection

SOLUTION:
  Rate limits on message sending (100/min per user)
  Rate limits on contact discovery (30/min per user)
  IP blocking after repeated violations
  Request throttling

IMPLEMENTATION:
  New tables:
  - api_rate_limits (track request counts)
  - api_blocked_ips (track blocked IPs)
  
  New class: /includes/RateLimiter.php
  - checkLimit() method
  - blockIP() method
  - isIPBlocked() method
  
  Update all APIs:
  - /api/messages.php: 100 requests/min
  - /api/contacts.php: 30 requests/min
  - /api/chat_prefs.php: 50 requests/min
  
  Response headers:
  - X-RateLimit-Limit
  - X-RateLimit-Remaining
  - X-RateLimit-Reset

RATE LIMIT RULES:
  POST messages: 100/min (prevent spam)
  GET contacts: 30/min (prevent scraping)
  GET messages: 200/min (normal use)
  POST prefs: 50/min (prevent abuse)
  
  IP blocking:
  - 10 failed auth → block 1 hour
  - 50 rate violations → block 6 hours

EFFORT: 3-4 hours
  - RateLimiter class: 1.5 hours
  - API integration: 1 hour
  - IP blocking: 45 min
  - Testing: 30 min

PRIORITY: 🟡 MEDIUM
  - Security hardening
  - Prevents spam/DDoS
  - Medium complexity
  - Ongoing tuning needed

TIMELINE: 2-3 weeks

PROTECTION:
  ✓ Prevent message spam
  ✓ Prevent contact enumeration
  ✓ Prevent brute force attacks
  ✓ DDoS mitigation
  ✓ Resource protection
