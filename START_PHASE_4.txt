================================================================================
TROUBLESHOOTING
================================================================================

ISSUE: Verification script shows errors
  SOLUTION:
    1. Check database credentials in config.php
    2. Ensure user has CREATE TABLE permission
    3. Check MySQL error log for details
    4. Try applying migration manually via phpMyAdmin

ISSUE: No logs appear in admin interface
  SOLUTION:
    1. Verify database migration was applied
    2. Send a test message
    3. Check that chat_audit_log table exists
    4. Review error logs for exceptions
    5. Verify API files include ChatAudit

ISSUE: Export button not working
  SOLUTION:
    1. Check PHP file permissions
    2. Ensure temp directory is writable
    3. Check PHP error logs
    4. Verify database has logs to export

ISSUE: Performance is slow
  SOLUTION:
    1. Check number of logs: SELECT COUNT(*) FROM chat_audit_log
    2. If > 1 million, run archival
    3. Verify indexes exist: SHOW INDEX FROM chat_audit_log
    4. Check available disk space

COMPLIANCE REPORTS EXPLAINED
================================================================================

GDPR REPORT:
- Shows all user data access activities
- Helps demonstrate compliance with Article 15 (Right of Access)
- Lists when each user accessed what data
- Export for auditor review

HIPAA REPORT:
- Tracks all healthcare communication
- Shows message send/read activities
- Helps comply with 164.312(b) audit requirements
- Export for healthcare compliance audits

SOX REPORT:
- Tracks financial communications
- Shows who accessed financial data and when
- Helps with § 404 internal control requirements
- Export for financial compliance audits

FAILED ACCESS REPORT:
- Shows all denied/failed access attempts
- Important for security incident investigation
- Helps identify suspicious activity
- Exports all access denials and errors

ACTIVITY SUMMARY:
- Overview of all activity in date range
- Shows counts by action and status
- Useful for general monitoring
- Export for management review

================================================================================
DATABASE INFORMATION
================================================================================

TABLES CREATED:
- chat_audit_log (main audit trail)
- chat_audit_log_archive (historical data)

KEY COLUMNS:
- id: Unique audit log entry ID
- tenant_id: Which tenant the event belongs to
- user_id: Who performed the action
- action: What action (send_message, read_message, etc.)
- target_user_id: Who was affected by the action
- message_id: Related message ID (if applicable)
- details: JSON field with additional context
- ip_address: Client IP address for security
- status: success, denied, failed, or error
- created_at: When the event occurred
- error_message: Error details if status is failed/error

RETENTION POLICY:
- Active logs: Last 90 days (recommended)
- Archived logs: Historical (move old logs to archive table)
- Run this monthly: ChatAudit::archiveOldLogs($tenantId, 90);

SECURITY:
✓ All failed/denied access attempts
✓ IP addresses for audit trail
✓ User agent information

EVERYTHING IS TIMESTAMPED AND TAGGED WITH:
✓ Tenant ID (for multi-tenancy)
✓ Branch ID (for organization)
✓ User ID (who did it)
✓ IP address (from where)
✓ Status (success/denied/failed)
